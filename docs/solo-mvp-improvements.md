# 单人主线改进与创新计划

更新：2026-09-10。

## 产品范围

用户已在第一阶段下线搭子匹配。当前只推进“选本、工具、档案”，不安排找人、互相点赞、组局、拼车或多人选本。本计划替代旧文档中的社交扩展路线。

目标是让一个用户独立完成：明确本次需求 -> 理解候选的适合点和风险 -> 使用工具记录游玩 -> 形成可修正的体验档案 -> 改善下一次选择。

## 改进方向

### 选本：先约束，再解释

长期口味和“这次想玩什么”分开。长期画像描述用户偏好；本次条件表达人数、可用时长、难度和不可接受内容。先过滤硬约束，再排序兴趣，不能让兴趣加分抵消硬禁忌。

内容展示分成适合点、风险、未知三部分。没有来源的风险字段显示待确认，规则分不包装成满意概率。后续可允许用户对比 2-3 本，观察更改某一条件后候选如何变化。

先修正当前标签和时长逻辑，再引入可编辑的硬约束。当前库只有示例内容，真实内容需补版本、来源和审核状态；不自动生成“真实评分”或假装已有授权资料。

### 工具：记录事实，保留推理过程

笔记按事实、推测、待验证组织，保留来源和发生顺序。计时、笔记和草稿应在弱网、切页及重进后恢复。下一阶段将记录归属从“某本”提升为“本次游玩”，以分开重玩和不同角色的信息。

AI 提示先帮助整理已知信息，再提示核查方向。每条具体提示关联用户已选择的笔记来源；无来源时承认信息不足。角色和幕权限准备好后再开放更深入的分级提示，不直接承诺模型绝不剧透。

### 档案：区分体验原因，允许修正

整体评分只提供弱信号。后续将剧本内容、角色体验、DM 和同桌氛围分开，优先使用用户明确确认的喜欢点和避雷点。一次低分不应永久否定整个类型；用户修改/删除记录后，推荐也应重新计算。

档案的价值是帮助下一次决策，优先完成可纠错、可回看、能解释推荐变化，再考虑海报或复杂统计。

## 创新实验

| 顺序 | 实验 | 最小交付 | 成功证据 |
| --- | --- | --- | --- |
| 1 | 可解释选本对比 | 对比 2-3 本的适合点、风险和缺失信息；修改本次条件后解释变化 | 用户更快确定候选，体验后的踩雷原因减少 |
| 2 | 体验归因反馈 | 打完用少量选项区分内容、角色、主持和同桌体验，确认后修正画像 | 下一次推荐更有帮助，用户能理解并撤销偏好变化 |
| 3 | 有来源的证据提示 | 用户选择已知笔记，AI 返回核查步骤和有效来源 ID | 来源有效、无越界补写，用户能继续推进 |

这些是待验证的产品假设。先完成本轮修复与基础闭环，再选择一项实验，不将更换模型或增加入口视为创新结果。

## 下一步验收

1. 工程：现有冒烟和新增回归通过；真实微信登录、真机锁屏、弱网和切换账号另行验收。
2. 内容：先整理 20-30 本可核验内容，确认来源与标签维护流程，再扩到 50-100 本。
3. 试用：邀请 30-50 名目标用户，分别观察高频和偶尔玩家的选本完成率、耗时、体验反馈及下一次使用意愿。
4. 指标：先定义曝光、选定、实际游玩和记录的分母；不使用旧路线中的单城市用户量或成局率作为推进条件。

## 接口演进原则

沿用 `{ code, data, message }`。目录查询采用可选参数区分完整目录与推荐，并增加分页信息；按 ID 的公开详情始终可访问。个人笔记和记录的新增、修改、删除必须校验所有权。AI 按服务端已知数据选择有界上下文。

`GET /api/scripts` 保留数组 `data`，新增 `catalog=1`、`collection=saved|dismissed`、`limit=1..100`、`offset`；响应增加 `pagination: { offset, limit, total, hasMore, nextOffset }`。默认推荐会过滤跳过，完整目录按 ID 排序且保留跳过内容。完整排序发生在分页之前，避免新增内容被前 100 条截断。

当前评分反馈按每本平均评分聚合，同一标签加入两条中性先验，合计影响最多正负 8 分。整体评分仅作为弱信号，后续再引入由用户确认的体验归因；不把低分直接解释成某个硬雷点。当前避雷仍是显式提醒和降权，硬禁忌筛选需要相应的用户选项后再启用。

AI 日次数包含已准入的请求，失败请求也计入防滥用额度；尚未调用供应商就结束的请求可取消预占。成本为预估准入与实际结算，严格账单上限仍需在供应商侧配置。
